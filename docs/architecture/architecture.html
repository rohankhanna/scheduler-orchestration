scheduler-orchestration: architecture (iteration 1)

Thin integration layer: job contract + scheduler adapter + operator controls (no scheduler core; no host mutation here).

Iteration-1 focus

  • Slurm-first integration
  • Thin, testable adapter
  • One job schema

Operator controls

  • dependency submission (DAG)
  • drain / stop-at-boundary
  • cancel / query

Hard boundary

  • no host mutation here
  • host changes belong in dotfiles
  • prefer adopting schedulers
